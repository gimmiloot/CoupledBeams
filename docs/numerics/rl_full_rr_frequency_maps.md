## Как менять диапазон

В массиве `maps` конфигурации редактируются `grid` и `fixed`. Например:

```json
{
  "name": "my_mu_map",
  "mode": "MU",
  "fixed": {"beta_deg": 30, "tau": 0},
  "grid": [0, 0.02, 0.04, 0.06, 0.08, 0.10]
}
```

Для BETA `grid` содержит градусы, `fixed` — `mu,tau`; для TAU `grid`
содержит τ, `fixed` — `beta_deg,mu`. Сетка должна строго возрастать.
Можно сохранить конфигурацию под другим именем и передать через `--config`.
Допускаются 0≤β≤180°, |μ|<1, |τ|<1; это проверка геометрии, а не гарантия
работоспособности базиса или точности 1D-модели во всём таком диапазоне.
ε=.005 и материал пока зафиксированы; изменение ε отклоняется.
Новые диапазоны вычисляются только при явном запуске пользователем.

Совпадающие точки A–B/C0–C1 и завершённых карт с тем же вычислительным
контрактом читаются повторно. Изменение сетки создаёт новый комплект,
но не требует пересчёта совпадающих точек. Разные μ и τ имеют разные ключи.
Числа `5` и `5.0` в JSON обозначают одну физическую конфигурацию.

## Перерисовка и чтение таблиц

```powershell
python scripts/analysis/map_rl_full_rr.py --plot-only results/rl_full_rr_maps/c100976d27f5c949
python scripts/analysis/map_rl_full_rr.py --tables-only results/rl_full_rr_maps/c100976d27f5c949
```

Эти режимы читают CSV и manifest, без импорта физического решателя,
сборки матриц, SVD, восстановления полей и поиска корней. `tables-only`
проверяет хеш таблицы и сообщает её путь/число строк; таблицу не перезаписывает.
Для иной компоновки изменить блок `plot` конфигурации либо передать
`--style path/to/style.json`. Пример файла оформления:

```json
{
  "layout": "split",
  "xlim": [0, 10],
  "yscale": "linear",
  "xlabel": "$\\beta$ (deg)",
  "ylabel": "$\\Lambda$",
  "legend_loc": [0.2, 1.02],
  "font_size": 12,
  "dpi": 300
}
```

`layout`: `all`, `split`, `both`; также доступны `ylim`, `figsize`, `title`,
`legend_font_size`, `title_font_size`. `legend_loc` принимает стандартное
положение Matplotlib либо пару координат относительно осей. Пользовательские
подписи должны сохранять физический смысл Λ. Изменённый стиль создаёт
отдельный каталог рисунков, не меняя CSV, manifest и исходные массивы.
Начальный вариант с легендой внутри осей сохранён; приведённые выше рисунки
перерисованы с вынесенной легендой, **с нулём новых решений**.

## Физический контракт и реализация

Канонические источники: [RL_FULL/Тимошенко](../theory/isotropic_two_springs_rl_timoshenko.md),
[индивидуальные сечения](../theory/isotropic_two_springs_thickness_asymmetry.md),
[верификация A–B](rl_full_rr_prefix_verification.md),
[верификация C0–C1](rl_full_rr_geometry_verification.md).
Точный RIGID/RIGID; E=ρ=l=1, ν=.3, k_s=5/6, b_i/h_i=4.

\[
L_{1,2}=l(1\mp\mu),\quad
h_{1,2}=\sqrt{12}l\varepsilon(1\mp\tau)/\sqrt{1+\tau^2+2\mu\tau},
\quad
\Lambda^4=\rho A_0\omega^2l^4/(EI_0).
\]

Общее опорное сечение даёт t_ref=200, Λ=√(200ω), Ω=Λ².
График читает именно столбец `Lambda`, а не `omega` или `Omega`.
В каждой точке записываются L_i,h_i,b_i,A_i,I_i,EA_i,EI_i,k_sGA_i,
ρA_i,ρI_i,J_i и проверка A₁L₁+A₂L₂=2A₀l.

Формулы и физические исходники не изменены. Программа переиспользует
`rl_full_rr_sections_prefix`: boundary, энергетический count_at, каталоги,
counted_prefix, восстановление форм и mode_gates. Порядок состояния,
индивидуальные коэффициенты, полная массовая форма и нормировка соответствуют
принятому C0-контракту. Контрольный прямой предел используется из A–B.

По Script Proliferation Control отдельная точка запуска оправдана новым
контрактом fast_plot/CSV/перерисовки: исторические CLI имеют фиксированные
ворота A–B/C0–C1 и Ritz в каждой точке. Новый физический решатель не создан;
на каждый набор параметров отдельная программа не требуется.

Локальная [frequency-map-v1](frequency_map_computation_policy.md) политика:
fast_plot, sorted_positions, K_plot=8, K_guard=9, strict_audit_default=false.
Последовательный predictor — только частоты предыдущей успешной точки.
Начальная верхняя граница без predictor — ω=1.6; с predictor — 1.1ω₉
(не ниже прежней начальной границы). Это начальная оценка, проверяемая счётом.
Сохраняются 160 count-запросов на попытку, глубина 30 и максимум три изменения
границы, прежние каталоги/контроль фактического обхода полюсов, допуски
корней 2·10⁻¹⁴, BC/ODE 10⁻⁹, энергии 5·10⁻⁸, Gram 5·10⁻⁷.
Неразрешённые кратности не разделяются искусственно; граничный кластер
завершается по прежнему ограниченному контракту K8.

Формы всего префикса восстанавливаются только для запрошенных физических
проверок и сохраняются в NPZ. MAC, tracking, полный certified_audit,
Ritz и удвоенная квадратура в каждой новой точке не запускаются.
Независимые опоры — ранее принятые проверки A–B/C0–C1.

После прохода сравниваются соседние запрошенные точки: триггер
maxₖ₌₁…₈|ωₖ(q_next)/ωₖ(q_prev)−1|>.2. Разрешён один повтор затронутой
правой точки без predictor, с начальной верхней границей 1.125·1.6.
Допуски прежние; требуются совпадение кратностей и частот в пределах 10⁻⁸.
Этот повтор проверяет локализацию тем же счётчиком и не называется независимым
Ritz. Несогласие остаётся отказом; плотная сетка автоматически не запускается.
Отказы сохраняются вместе с промежуточной диагностикой, в CSV частоты пусты,
на графике разрыв и вертикальная отметка. Завершённый отказ не перезаписывается.

## Происхождение и сохранность

Новое семейство — `results/rl_full_rr_maps/`. Identity включает физический
контракт, полную сетку, локальную политику, допуски, версии зависимостей,
Git HEAD и SHA256 фактических исходников. Git HEAD сам по себе недостаточен:
имеются незакоммиченные исходники, поэтому используются их хеши.
Manifest связывает каждую строку карты с JSON/NPZ или принятым внешним
источником и его хешем. Точки публикуются атомарно после локальных проверок;
при прерывании повторный запуск читает уже сохранённые точки.
Исходные принятые комплекты не копируются и не перезаписываются.

CSV вместе с manifest достаточны для рисунка без NPZ. Каталог `figures/`
имеет отдельные fingerprint стиля и исходной таблицы. Локальные результаты
игнорируются Git; ссылки в отчёте не означают публикации данных в GitHub.
